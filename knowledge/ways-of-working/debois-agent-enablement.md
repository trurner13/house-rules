# Build an Agent Enablement function to scale AI coding across the org

**Principle:** Coding agents don't scale by themselves, and neither do the teams using them. Stand up a dedicated Agent Enablement function — the next evolution of DevOps and Platform Engineering — and shift your reflex from fixing the code to fixing the system that produces the code.

**Why:** Individual developers getting good with agents doesn't add up to organisational capability. Without a deliberate function, knowledge stays trapped in individuals, context and harnesses get rebuilt ad hoc, governance is an afterthought, and the gains plateau. Most "good engineering practice" for humans turns out to be good for agents too — so the discipline is organisational, not just technical.

**How to apply:**
- **Organise around three pillars.** Enablement (help people and agents get good — training, shared context, patterns), Platform (the harnesses, tooling, shared context libraries, skill/harness registries agents run on), and Governance (guardrails, security, policy). Treat these as standing concerns, not projects.
- **Audit across three org lenses.** Run each pillar against three levels — Developer, Team Lead, and VP of Engineering. The Enablement × Platform × Governance by Developer × Team-Lead × VP matrix is your gap-analysis grid; walk every cell.
- **Use the barrel mental model.** All staves of the barrel must rise together: "if you have one piece of the barrel that is very low, the water will pour through there." Find your lowest stave and raise it before optimising the strong ones.
- **Fix the system, not the code.** When an agent produces a bad result, don't just patch the output — change the harness, context, or process that caused it, so the fix compounds.
- **Apply the Context Development Lifecycle to the org chart**, treat agents as team members, and create the role of **AI product engineer**.
- **Track agent KPIs** like turns-per-task; treat **continuous learning as the next CI/CD**.
- Accept there is no playbook — adapt, don't copy. See `evals` for measuring agent quality.
